# 修炼 B 版组件

最新进度条采用横向浅方槽：居中显示“修炼进度 N%”，蓝灰至雾蓝的柔和渐变，标签直接读取显示控制器的同一个0–100数值，完成停留期间同步显示100%。不重新生成任何图片。

突破入口依据 `getRealmSnapshot().entryAvailable`（原存档解锁字段）显示，解锁后常驻中央，不以当前是否可操作作为显示条件；点击继续走境界详情路由，不直接提交突破。微光依据 `readiness.confident`，每次刷新更新，暂停、剧情遮挡、正在渡劫时不亮。只读估算依据原事件2106/2196的逐tick四舍五入攻防，普通突破保留25%当前气血余量；大境界要求已装备材料，首轮估计在24月内完成且有25%余量。圣境或未知公式数据不做高把握提示。此为保守估算，不承诺成功或品级，不修改游戏状态。

当前修炼双按钮采用最终选择的 A「月白玉签」。独立控件样式在 `moon-actions.css`，按已生成的 `exec-56a09954-16e6-42d6-aaf8-79d9a7741475.png` 还原：月白胶囊主键、无底色文字副键、细下划线和箭头，不重新生成素材。文字与状态由真实按钮渲染，继续使用原 train/stop 和法门弹层事件。角色栏、任务栏、头像与底栏保留原有通透深蓝样式。进度轨道为 12 CSS 单位（750 设计宽度下 24px），冰蓝渐变与轻内凹。

`cultivation-progress.js` 单独管理修炼条显示：逐帧读取真实本层进度；检测回绕或层数增加，80ms 补齐至100%，停留100ms后接入当前真实进度。显示状态独立于 DOM 生命周期，避免升级重绘丢掉满格；暂停与切换法门不会伪造完成。该模块不修改游戏数据。`analysis/cultivation-progress-tests.cjs` 覆盖回绕、DOM重建、延迟层数快照、暂停、换法门、满层自动停修。

入口：`index.html` 加载 `moon-ui.js`、`moon-ui.css`，`portrait.js` 将实时快照交给 `MobileMoonUI.render`。其他页面继续使用现有渲染器。共享七项导航沿用真实路由与设置事件，仅替换样式。

组件：角色信息栏、内嵌任务（保留原任务内容和快捷操作）、完整打坐场景、渐变压暗操作区、本层进度条、修炼启停、法门详情与选择弹层、共享底部导航。

场景素材：`assets/cultivation-moon.png`，纯画面，不含文字、按钮。头像沿用已有 `assets/cultivator.webp`。图标为统一线宽 SVG；文字、数值、进度与控件均由 DOM 实时绘制。

数据：法门、耗时、上限、增益和解锁条件来自 GameAdapter。进度条表示本层修炼进度，旁边数字表示当前层数 / 真实上限，不使用设计稿示例上限。UI 称“气血”，底层仍读取原真气字段，不改变数值规则。未找到玩家名 / 综合实力字段，使用“道友”和“实力详情”入口。

交互：原 train/stop 命令保持不变；更换法门打开详情，选择已解锁法门调用原修炼入口。锁定 / 圆满项禁用。任务和法门展开状态在实时刷新后保留；弹层支持关闭、Escape、键盘焦点循环。设置、属性、境界、其他五项导航继续原路由。

验证：`analysis/moon-ui-check.cjs` 用独立快照检查 750×1334、375×667、390×844，检查素材、任务展开、法门开闭与锁定状态，不加载存档。`analysis/cultivation-entry-tests.cjs` 检查原启停逻辑。实际浏览器截屏见 `qa/moon-ui`。

2026-10-17 法门弹层改为紧凑列表：固定标题与当前法门摘要，列表独立滚动；每项直接展示层数、耗时、下层三项增益，当前加成按需展开。修炼成功后关闭弹层并返回入口焦点；修炼中的当前法门、锁定项、圆满项禁用，保留 Escape 与包含详情入口的键盘焦点循环。
