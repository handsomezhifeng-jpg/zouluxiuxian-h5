## 洞府适配

`model.js` 通过独立配置副本将地图命名为云归谷、清溪境、烟雨峰。对应设施：黏土矿→灵矿，草药田→灵田，炼丹炉→炼丹房，瓷窑→炼器房，鱼塘→御兽坊，道观→修室，书院→藏经阁，宗祠→护派大阵。其他辅助生产设施沿用原建筑美术。

原组件明确不含生产与居民系统，因此这里新增经营层，而非声称这些功能来自原包：

- 每个新档初始12弟子，10人默认分配；全地图共享人数约束，可分配、撤回和招募。
- 每15秒按派驻人数与建筑等级结算；营造完成前不生产。消耗实际府库材料，产出进入待收取区。
- 灵矿产府库灵石与矿石，灵田产灵草与灵食，炼丹/炼器产丹药/器胚，御兽坊积累灵兽修为，修室积累弟子修为，藏经阁积累心得，大阵产阵法灵力。
- 灵木、灵纸、灵棉、灵布等辅助生产链有材料输入和产出。原 `source_r*` 营造材料映射为灵矿石，原典籍费用映射为藏经心得，数量沿用原定义，避免出现无法生产的原城镇物料。
- 每10分钟检查一次来袭；消耗已入库阵力抵御，阵力不足损失5%府库灵石，不破坏角色存档。
- 离线经营最多8小时，不重复收取；施工时间仍由原引擎推进。

初始营造为开局赠送设施，随后所有建造与升级正常扣费。府库与弟子养成独立于原角色资源；丹药、器胚、灵兽修为等目前为洞府库存，不自动转成角色消耗品、装备或原灵兽属性。

## 生命周期与存档

`cave-host.js` 仅在进入洞府时动态加载组件，避免在游戏启动时下载全部城建美术。记录保存在原运行时 `runtime.storage` 的 `mobile-cave-estate-v1:<slot>`。离开页面销毁视图和输入，经营模型继续推进；刷新从同档恢复。无效存档原样保留并显示载入错误。保存失败显示提示并重试。重新开始游戏前等待洞府保存队列关闭，再按原逻辑清档。

底部只替换原功法入口为洞府，功法可从洞府页右上进入。其余导航沿用既有美术与坐标；旧复合图中该槽位通过透明遮罩排除，文字独立渲染，没有矩形盖字。原金线边框上下贯通。
